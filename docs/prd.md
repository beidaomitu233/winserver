## 一、简介

### 1. 目的

本文档用于定义 WinServer V1.0 的产品需求、页面结构、交互规则、系统闭环、异常处理和验收口径。文档面向产品、前端、后端、数据库、测试和审查模型，要求后续执行模型可以按本文逐项拆解任务并实施。

WinServer 的核心目标是：帮助新手在 Windows 上快速、简单、可靠地搭建本地 Web 开发环境，避免手动下载、解压、配置、启动、写 hosts、排查端口等复杂操作。用户打开软件后，应首先看到整洁的服务启动面板，并能通过少量按钮完成安装、启动、建站和访问。

### 2. 范围

本 PRD 覆盖 WinServer 第一阶段必须完成的能力：

- 首页启动面板。
- 服务启动、停止、重启和状态检测。
- Nginx/PHP 运行环境安装、导入、检测和删除。
- 网站创建、编辑、启用、停用、删除和访问。
- PHP 多版本切换。
- hosts 自动维护。
- 配置文件查看与编辑。
- 日志查看、搜索、清空。
- 端口检查与故障诊断。
- 设置、路径、备份、phpMyAdmin 地址。
- 数据库页基础能力和 MySQL 可用性判断。
- 文件页只读浏览能力。

本 PRD 不包含：

- 具体代码实现。
- 详细数据库迁移 SQL。
- 安装包签名和发布流水线。
- 云同步、账号体系、插件市场。
- Docker、远程服务器、生产环境部署。

### 3. 名词术语

| 名词 | 说明 |
| --- | --- |
| 服务 | WinServer 管理的本地进程或 Windows 服务，如 Nginx、PHP FastCGI、MySQL、Redis |
| runtime | 某个可运行软件版本的安装目录和清单，如 `nginx-1.26.3`、`php-8.3-nts-x64` |
| bundled runtime | 随 WinServer 安装包附带的运行环境压缩包或目录 |
| 站点 | 一个本地 Web 项目，包含域名、端口、根目录、服务器类型、PHP runtime |
| vhost | Nginx/Apache 的虚拟主机配置文件 |
| hosts managed 区块 | WinServer 在 hosts 中维护的专属区块，不能覆盖用户手写内容 |
| desired_state | 用户期望状态，如希望服务运行 |
| actual_state | Agent 真实检测状态，如运行中、失败、降级 |
| 健康检查 | 进程、端口、配置、HTTP/PHP 响应等多层检测 |
| 回滚 | 操作失败后恢复旧配置、旧 hosts、旧数据库记录和旧服务状态 |

## 二、用户角色描述

| 用户角色 | 用户描述 | 核心诉求 |
| --- | --- | --- |
| 新手开发者 | 不熟悉 Nginx、PHP、hosts、端口和配置文件 | 打开软件即可安装和启动，不需要命令行 |
| PHP 开发者 | 同时维护多个 PHP 项目 | 多站点、多 PHP 版本切换，失败可排查 |
| 前端开发者 | 需要本地静态服务或反向代理 | 快速启动 Nginx，创建静态目录站点 |
| 测试人员 | 验证本地项目和软件回归 | 稳定重现环境，查看日志和配置 |
| 高级用户 | 了解配置文件，希望手动微调 | 可编辑配置，但保存前后有校验和备份 |

权限说明：

- 第一阶段为本地单用户，不做登录。
- UI 默认普通权限运行。
- 写 hosts、注册服务、修改受保护目录由受控 Agent 或明确提权流程完成。
- 前端不允许执行任意命令。

## 三、产品概述

### 1. 产品目标

| 目标 | 说明 | 完成标准 |
| --- | --- | --- |
| 打开即用 | 用户启动应用后看到简洁启动页 | 3 秒内首页可交互，黑屏/白屏不超过 2 秒 |
| 启动可信 | 服务显示运行中必须来自真实检测 | PID、端口、配置、健康检查均通过 |
| 建站闭环 | 从填写表单到本地域名访问完整打通 | vhost、hosts、reload、HTTP/PHP 检查通过 |
| 安装可靠 | runtime 安装/导入必须校验完整性 | 关键文件、版本探测、端口分配、数据库登记通过 |
| 失败可解释 | 用户知道失败原因和下一步 | 错误包含对象、原因、建议、日志入口 |
| 失败可恢复 | 坏配置不能破坏已有站点 | 操作失败自动回滚或提供恢复入口 |

### 2. 总体流程

首次使用流程：

```text
打开 WinServer
  -> 初始化本地数据目录和 SQLite
  -> 检测 bundled runtime 和本机已安装 runtime
  -> 首页展示 Nginx/PHP/MySQL/Redis 服务卡片
  -> 用户安装或导入 Nginx
  -> 用户安装或导入 PHP
  -> 用户点击启动服务
  -> 用户创建站点
  -> WinServer 写 vhost 和 hosts
  -> Nginx reload
  -> 浏览器访问本地域名
```

日常使用流程：

```text
打开 WinServer
  -> 首页显示真实服务状态
  -> 点击启动全部或单个服务
  -> 进入网站页创建/维护站点
  -> 进入日志/配置/诊断处理问题
  -> 关闭 UI 后服务可按配置继续运行或停止
```

### 3. 产品结构图

交互框架：Windows 桌面应用，左侧导航 + 顶部状态栏 + 右侧工作区。

页面清单：

- 首页：服务启动卡片、启动全部、停止全部、快捷入口、最近错误。
- 网站：站点列表、新建/编辑弹窗、启用/停用、删除、打开、配置。
- 数据库：MySQL 管理、phpMyAdmin、备份、导入导出。
- 软件：runtime 检测、安装、导入、删除、下载进度。
- 文件：只读目录浏览。
- 日志：结构化操作记录、搜索、结果筛选、自动刷新、清空。
- 设置：常规、网络、路径、安全、备份、配置文件。

## 四、功能需求说明

### 1. 首页启动面板模块

#### 1.1 首页总体

**页面位置**

应用启动后默认进入首页，左侧导航第一项“首页”。

**页面目标**

首页只解决一个核心问题：让用户最快知道“服务能不能启动、有没有运行、哪里出错”。首页不是监控大屏，不展示复杂教程，不堆叠大量 tag 和说明。

**页面结构**

顶部：全局操作区  
主体：服务启动卡片区  
下方：快捷入口和最近问题区

| 区域 | 内容 | 展示要求 |
| --- | --- | --- |
| 全局操作区 | 启动全部、停止全部、刷新状态 | 按钮清晰，放在首屏顶部或卡片上方 |
| 服务启动卡片区 | Nginx、PHP、MySQL、Redis 卡片 | 卡片尺寸大，主按钮醒目 |
| 快捷入口区 | 创建站点、软件管理、日志、端口检查 | 使用图标按钮或小卡片，不抢服务卡片视觉 |
| 最近问题区 | 最近一条 failed/degraded 错误 | 一行摘要 + 查看详情 |

**服务卡片字段**

| 字段 | 展示样式 | 数据来源 |
| --- | --- | --- |
| 服务名称 | 大号文字，如 Nginx | `service.name` |
| 状态 | 状态点 + 文案 | `service.state` |
| 端口 | 小号文本，如 `:80` | `service.port` |
| 主按钮 | 启动/停止/安装/查看问题 | 根据 `installed` 和 `state` 计算 |
| 次按钮 | 重启/配置/日志 | 根据服务能力展示 |
| 错误摘要 | 红色短文本 | `service.error_message` |

**状态到按钮映射**

| 条件 | 主按钮 | 次按钮 | 是否可点击 |
| --- | --- | --- | --- |
| `installed=false` | 安装/导入 | 软件页 | 可点击 |
| `installed=true` 且 `state=stopped/installed/unknown` | 启动 | 配置 | 可点击 |
| `state=starting` | 启动中 | 日志 | 主按钮禁用 |
| `state=running` | 停止 | 重启、配置 | 可点击 |
| `state=stopping` | 停止中 | 日志 | 主按钮禁用 |
| `state=failed` | 查看问题 | 重试、日志 | 可点击 |
| `state=degraded` | 查看问题 | 重启、日志 | 可点击 |

**交互规则**

- 首页加载时调用 `state.getFast` 或 `state.get`，展示骨架屏，不展示旧假数据。
- 用户点击刷新时重新拉取 state，按钮进入 1 秒以内的 loading。
- 单个卡片操作期间只禁用当前卡片按钮，不锁死整个页面。
- 启动/停止/重启成功后，必须使用后端返回 state 更新页面。
- 启动接口返回错误时，卡片进入 failed 或保留原状态，并展示错误摘要。
- “查看问题”打开诊断详情弹窗或跳转日志页，必须携带 serviceId。

**空状态**

| 场景 | 展示 |
| --- | --- |
| 没有任何服务数据 | 显示“未检测到服务配置”，提供“检测本机环境”和“进入软件管理” |
| Agent 连接失败 | 显示错误页，提供“重试连接”和“查看 Agent 日志” |
| 服务未安装 | 卡片显示未安装，不展示启动按钮 |

**异常与边界处理**

| 异常 | 前端表现 | 后端要求 |
| --- | --- | --- |
| 端口被占用 | 卡片 failed，错误摘要显示端口 | 返回 `PORT_OCCUPIED`、端口、PID、进程 |
| 配置错误 | 卡片 failed，提供配置入口 | 返回配置文件路径和 stderr |
| exe 缺失 | 卡片未安装或 corrupted | 返回缺失路径 |
| 启动超时 | 卡片 failed | 写操作日志，记录超时时长 |
| Agent 无响应 | 全局错误 | Tauri command 返回连接失败 |

**依赖接口**

| 操作 | Tauri command | Handler 方法 | 请求参数 | 响应 |
| --- | --- | --- | --- | --- |
| 获取状态 | `get_state` | `state.get` | 无 | `AppState` |
| 启动服务 | `service_start` | `service.start` | `serviceId` | `{ state, message }` |
| 停止服务 | `service_stop` | `service.stop` | `serviceId` | `{ state, message }` |
| 重启服务 | `service_restart` | `service.restart` | `serviceId` | `{ state, message }` |
| 启动全部 | `suite_start` | `suite.start` | 无 | `{ state, summary }` |
| 停止全部 | `suite_stop` | `suite.stop` | 无 | `{ state, summary }` |

**验收标准**

- [ ] 首页服务卡片为首屏主要视觉，不被说明文字和 tag 淹没。
- [ ] 未安装、停止、启动中、运行中、失败、降级状态均有明确视觉。
- [ ] 启动成功必须来自真实检测，不允许点完按钮直接显示运行中。
- [ ] 失败时可从首页进入日志或诊断。
- [ ] 刷新、启动、停止、重启均有 loading 和错误反馈。

#### 1.2 启动全部/停止全部

**触发方式**

首页全局操作区点击“启动全部”或“停止全部”。

**处理范围**

只处理 `auto=true` 且 `installed=true` 的服务。用户可在一键启动旁勾选启动项，选择写入 SQLite 并在后续启动和应用重启后保持。MySQL 5.7/8.0 启动项互斥。未安装服务不参与启动，不算失败，但在汇总中提示跳过。

**交互流程**

点击启动全部：

```text
弹出确认或直接执行
  -> 按依赖顺序启动 PHP/MySQL/Redis/Nginx
  -> 每个服务独立执行 service.start
  -> 记录每项成功、失败、跳过
  -> 返回汇总
  -> 首页刷新每张卡片状态
```

点击停止全部：

```text
确认停止
  -> 按依赖逆序停止 Nginx/PHP/MySQL/Redis
  -> 每个服务独立执行 service.stop
  -> 返回汇总
```

**汇总展示**

| 字段 | 说明 |
| --- | --- |
| 成功数量 | 已启动或已停止的服务数量 |
| 失败数量 | 处理失败的服务数量 |
| 跳过数量 | 未安装或 auto=false |
| 失败列表 | 服务名 + 错误摘要 |

**验收标准**

- [ ] 单个服务失败不阻断后续服务。
- [ ] 勾选结果重启应用后保持，一键启动不处理未勾选服务。
- [ ] MySQL 5.7/8.0 不会同时成为一键启动项。
- [ ] 汇总展示成功、失败、跳过。
- [ ] 失败服务写入 operation_logs。
- [ ] 停止全部不误杀外部同名进程。

### 2. 服务管理与状态检测模块

#### 2.1 服务状态模型

**状态枚举**

| 状态 | 说明 | 页面表现 |
| --- | --- | --- |
| `installed` | 已安装但未启动 | 灰色，可启动 |
| `starting` | 启动中 | 蓝色 loading，按钮禁用 |
| `running` | 运行中 | 绿色，可停止/重启 |
| `degraded` | 部分异常 | 橙色，可查看问题 |
| `stopping` | 停止中 | 灰蓝 loading |
| `stopped` | 已停止 | 灰色，可启动 |
| `failed` | 启动或运行失败 | 红色，可查看问题 |
| `unknown` | 未检测或不可判定 | 灰色，提示刷新 |

**状态检测层级**

| 检测层 | Nginx | PHP | MySQL/Redis |
| --- | --- | --- | --- |
| 进程 | master/worker PID 存在 | php-cgi PID 存在 | mysqld/redis PID 存在 |
| 端口 | 80/443 或配置端口监听 | FastCGI 端口监听 | 3306/6379 监听 |
| 配置 | `nginx -t` | `php -v`/php.ini 可读 | 配置可读 |
| 健康 | HTTP 响应 | FastCGI 或测试站点响应 | 握手/SELECT 1/PING |

**状态判断规则**

- 全部检测通过：`running`。
- 进程存在但健康失败：`degraded`。
- 用户期望运行但进程消失：`failed`。
- 未安装或关键文件缺失：`installed=false` 或 `failed`。
- 检测失败但原因不明：`unknown` 并记录日志。

#### 2.2 单服务启动

**触发方式**

首页服务卡片“启动”按钮，或未来服务详情页启动按钮。

**前端交互**

- 点击后当前按钮变为 loading，文字“启动中”。
- 当前卡片不能重复点击。
- 页面底部可显示“正在启动 Nginx...”。
- 超过 10 秒未返回时显示“仍在启动，可查看日志”，但不自行判定成功。

**后端流程**

```text
读取 service_instances
  -> 校验 installed=true
  -> 校验 exe/cwd/config_file
  -> 端口占用检查
  -> Nginx 配置预检查或 PHP 版本检查
  -> 启动进程
  -> 记录 PID
  -> 等待端口监听
  -> 执行健康检查
  -> 更新 desired_state 和 actual_state
  -> 写 operation_logs
```

**错误提示规范**

| 错误 | 用户提示 | 下一步 |
| --- | --- | --- |
| 未安装 | “Nginx 尚未安装，请先安装或导入” | 跳转软件页 |
| exe 不存在 | “启动文件不存在：...” | 重新导入 |
| 端口占用 | “80 端口被 xxx.exe 占用” | 查看占用/修改端口 |
| 配置错误 | “配置检查失败，第 X 行...” | 打开配置 |
| 启动后退出 | “进程启动后立即退出” | 查看 stderr/日志 |

**验收标准**

- [ ] 启动前检查 runtime 和端口。
- [ ] 启动后获取真实 PID。
- [ ] 端口未监听不得显示 running。
- [ ] 健康检查失败时显示 degraded 或 failed。

#### 2.3 单服务停止

**触发方式**

首页服务卡片“停止”按钮。

**后端流程**

```text
读取当前 PID 和服务 ID
  -> 判断 PID 是否仍由 WinServer 管理
  -> 优先 graceful stop
  -> 等待进程退出
  -> 等待端口释放
  -> 超时后终止当前服务进程组
  -> 更新状态
```

**安全要求**

- 不允许按进程名全局强杀。
- 不允许杀掉外部软件启动的 `nginx.exe` 或 `php-cgi.exe`。
- 如果 PID 已不存在，应视为 stopped，并更新状态。

**验收标准**

- [ ] 服务停止后端口释放。
- [ ] 停止外部同名进程测试通过。
- [ ] 停止失败时保留错误提示。

**验收标准**

- [ ] 两个站点可使用不同 PHP。
- [ ] 切换后实际 PHP 版本与选择一致。
- [ ] 失败后旧站点仍可访问。

### 6. hosts 管理模块

#### 6.1 hosts 维护范围

WinServer 只能维护自身 managed 区块，不得覆盖用户其他内容。

managed 区块格式：

```text
# >>> WinServer managed
127.0.0.1 demo.local
127.0.0.1 api.demo.local
# <<< WinServer managed
```

#### 6.2 写入规则

**触发场景**

- 创建站点。
- 编辑站点域名。
- 启用站点。
- 停用站点。
- 删除站点。

**写入流程**

```text
读取 hosts
  -> 解析 managed 区块
  -> 检查用户区是否已有同域名
  -> 备份 hosts
  -> 修改 managed 区块
  -> 写回 hosts
  -> 验证写入结果
```

**冲突处理**

| 场景 | 处理 |
| --- | --- |
| 用户区已有同域名 | 阻止写入，显示冲突行 |
| managed 区块重复 | 自动去重 |
| hosts 无权限 | 返回 `HOSTS_PERMISSION_DENIED`，引导提权 |
| hosts 文件不存在 | 返回系统异常，不自动创建系统 hosts |

**验收标准**

- [ ] 用户手写 hosts 内容不被修改。
- [ ] 删除站点只删除对应 managed 域名。
- [ ] 权限不足时配置和数据库能回滚。

### 8. 日志中心模块

#### 8.1 日志页总体

**页面位置**

**页面结构**

**日志来源**

仅保留 `operation`，数据来自 SQLite `operation_logs`。服务自身日志文件仍由各运行环境维护，但不再作为日志中心的来源类型。

**搜索与刷新**

| 元素 | 类型 | 说明 |
| --- | --- | --- |
| 搜索框 | 文本输入 | 按关键字过滤日志 |

| 自动刷新 | Switch | 默认开启，每 3 秒刷新 |
| 清空 | 危险按钮 | 二次确认后清空操作日志表 |

- 单次最多展示 500 条，数据库最多保留最近 5000 条。
- 展示 action、target、success、errorCode、message、details 和 createdAt。
- `details` 中的密码、token、密钥必须替换为 `[REDACTED]`，配置正文只记录长度。

**空状态**

| 场景 | 文案 |
| --- | --- |

| 操作日志为空 | “暂无操作记录” |

**验收标准**

- [ ] 服务、站点、配置、数据库、软件和设置关键操作可追踪。
- [ ] 密码、token、密钥和配置正文不写入明文详情。
- [ ] 清空操作日志不会删除服务自身日志文件。

| 页面切换 | 500ms 内 |
| 服务状态刷新 | 2 秒内 |
| 日志读取 | 大日志不阻塞 UI |
| 下载/安装 | 后台执行，有进度 |

### 2. 兼容性需求

- Windows 10/11。
- 普通用户启动 UI。
- 支持路径中包含空格和中文。
- 支持 IPv4 `127.0.0.1`。
- 支持默认浏览器打开本地域名。

### 3. 安全需求

- 不允许前端执行任意命令。
- 不允许把用户输入直接拼接到命令字符串。
- 写文件路径必须来自可信配置。
- 密码不写日志。
- 下载包必须校验。
- 删除站点不删除源码。

### 4. 监控和日志需求

- 所有用户触发的修改操作写 operation_logs。
- 服务启动失败写失败原因。
- 安装失败写阶段和错误。
- 配置保存写备份路径。
- 健康监控发现异常写日志。

## 七、风险分析

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| hosts 写入权限不足 | 站点域名不可访问 | Agent 提权或明确提示手动授权 |
| Nginx/PHP 版本差异 | 配置模板不兼容 | runtime 探测和适配器 |
| 端口被外部占用 | 服务启动失败 | 端口诊断和修改入口 |
| 配置错误破坏全部站点 | 多站点不可用 | 临时配置验证和回滚 |
| 下载源不可用 | runtime 无法安装 | 支持 bundled 和本地导入 |
| 页面显示缓存状态 | 用户误判服务运行 | 状态必须来自 Agent 检测 |
| 大日志卡顿 | UI 无响应 | 尾部读取和行数限制 |
