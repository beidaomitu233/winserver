# WinServer 验收文档

## 1. 验收原则

WinServer 的验收只承认真实闭环，不承认页面展示、接口返回或数据库写入中的任一单点完成。

完整闭环定义：

```text
用户操作
  -> 前端提交真实参数
  -> Tauri command 调用 Agent
  -> Agent 完成校验、配置、进程、文件、数据库处理
  -> 第三方服务真实运行或真实失败
  -> Agent 执行检测
  -> 前端展示真实结果
  -> 自动测试和人工验收通过
```

禁止标记完成的情况：

- [ ] 只有页面，没有真实接口。
- [ ] 只有接口，没有前端接入。
- [ ] 只写数据库，没有配置或进程副作用。
- [ ] 只启动进程，没有 PID、端口、健康检查。
- [ ] 使用 mock 数据、硬编码成功、临时返回值。
- [ ] 异常路径没有回滚。
- [ ] 测试失败后继续领取下一任务。
- [ ] 留有 TODO、空方法、未实现分支并影响验收功能。

## 2. 完成定义

每个功能必须同时满足：

- [ ] 前端入口清晰可用。
- [ ] 前端表单校验覆盖空值、格式、边界值。
- [ ] 调用真实 Tauri command。
- [ ] 后端接口完成参数校验。
- [ ] 后端业务逻辑完成真实系统操作。
- [ ] SQLite 读写正确，刷新和重启后仍一致。
- [ ] 配置文件生成、保存或回滚正确。
- [ ] 第三方程序真实启动、停止或被检测到。
- [ ] 服务状态来自进程、端口、配置和健康检查。
- [ ] 成功和失败均写入操作日志。
- [ ] 失败时返回明确错误原因。
- [ ] 失败时不会破坏旧配置和其他站点。
- [ ] 单元测试通过。
- [ ] 集成测试通过。
- [ ] 系统测试通过。
- [ ] 人工验收步骤通过。
- [ ] 构建、打包或启动命令通过。

任何一项未通过，功能状态保持“未完成”。

## 3. 验收环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 |
| 权限 | 普通用户启动 UI；写 hosts 或服务安装需要受控管理员能力 |
| 端口 | 默认 80、9073/9074/9081/9082/9083、3306/3307 可检测 |
| runtime | 至少一个 Nginx，一个 PHP；系统测试建议两个 PHP 版本 |
| 浏览器 | 系统默认浏览器可打开本地域名 |
| 数据库 | SQLite 数据目录可写 |
| 网络 | 在线下载测试可单独执行；离线验收必须覆盖 bundled/导入 |

## 4. 测试分层

### 4.1 单元测试

目标：验证纯逻辑、参数校验、状态转换、模板生成、错误映射。

必须覆盖：

- [ ] 服务状态枚举转换。
- [ ] 端口参数 0、1、80、65535、65536。
- [ ] 域名合法/非法/重复。
- [ ] Windows 路径合法性和绝对路径判断。
- [ ] Nginx vhost 模板生成。
- [ ] hosts managed 区块增删。
- [ ] runtime manifest 校验。
- [ ] 错误码到前端提示映射。
- [ ] 日志尾部读取和搜索。
- [ ] 设置字段类型校验。

建议命令：

```text
cargo test
npm run test
```

### 4.2 集成测试

目标：验证 Tauri command/Agent handler/SQLite/文件系统之间的协作。

必须覆盖：

- [ ] `state.get` 返回完整 AppState。
- [ ] `runtime.import` 写入 runtime、software、service_instances。
- [ ] `software.installBundled` 解压或复制 runtime 并登记。
- [ ] `service.start` 对未安装服务返回明确错误。
- [ ] `service.start` 对端口冲突返回 `PORT_OCCUPIED` 或等价可读错误。
- [ ] `site.create` 成功写 sites、vhost、hosts。
- [ ] `site.create` 在配置错误时回滚文件和数据库。
- [ ] `site.switchPhp` 成功更新 vhost 和站点引用。
- [ ] `config.save` 创建备份并返回最新 state。
- [ ] `log.list` 返回结构化操作记录，搜索和 500 条上限不阻塞。

建议命令：

```text
cargo test --test api_integration
cargo test --test bundled_install
cargo test --test prd_acceptance
```

### 4.3 前端组件/交互测试

目标：验证页面状态、按钮、弹窗、错误展示。

必须覆盖：

- [ ] 首页服务卡片状态渲染。
- [ ] 首页启动/停止按钮 loading 和禁用状态。
- [ ] 软件页导入/安装按钮状态。
- [ ] 网站新建表单校验。
- [ ] 网站编辑弹窗回显。
- [ ] 启用/停用状态切换。
- [ ] 配置编辑器加载、保存、错误提示。
- [ ] 端口检查弹窗可展示占用结果。
- [ ] 日志页搜索、清空、空状态。
- [ ] 设置页保存字段后刷新。

建议命令：

```text
npm run test
npx playwright test
```

### 4.4 系统测试

目标：在真实 Windows 环境中验证完整业务链路。

必须覆盖：

- [ ] 首次启动应用。
- [ ] bundled/runtime 安装或本地导入。
- [ ] 启动 Nginx。
- [ ] 启动 PHP FastCGI。
- [ ] 创建站点。
- [ ] 通过本地域名访问。
- [ ] PHP 文件真实执行。
- [ ] 切换 PHP 版本。
- [ ] 停用和启用站点。
- [ ] 删除站点。
- [ ] 重启应用后状态恢复。
- [ ] 故障注入后错误提示和回滚。

## 5. 应用启动体验验收

- [ ] 任务编号：AC-START-001
  模块：应用启动
  目标：验证双击应用后的真实可用体验。
  操作步骤：关闭所有 WinServer 窗口；双击启动；观察窗口出现、加载状态、首页可交互时间。
  验收标准：1 秒内出现窗口或加载界面；黑屏/白屏不超过 2 秒；3 秒内首页可交互；Agent 初始化失败时显示错误页和重试入口。
  测试要求：冷启动、热启动各执行 3 次，记录最长耗时。

- [ ] 任务编号：AC-START-002
  模块：启动状态恢复
  目标：验证应用重启后读取真实服务状态。
  操作步骤：启动 Nginx/PHP；关闭 UI；保持或停止服务；重新打开 UI。
  验收标准：服务卡片状态与真实进程和端口一致，不以关闭前缓存为准。
  测试要求：覆盖服务仍在运行、服务已退出、端口被其他程序占用三种场景。

## 6. 首页验收

- [ ] 任务编号：AC-HOME-001
  模块：首页视觉与信息密度
  目标：首页成为整洁启动页面。
  操作步骤：打开首页，检查首屏元素。
  验收标准：服务卡片为首屏主要视觉；无冗余 tag、长说明、重复 badge；启动/停止/重启入口清晰；最近错误只展示摘要。
  测试要求：桌面宽屏和窄窗口各截图审查。

- [ ] 任务编号：AC-HOME-002
  模块：首页服务操作
  目标：验证服务卡片操作真实生效。
  操作步骤：对 Nginx 和 PHP 依次执行启动、停止、重启。
  验收标准：按钮 loading 正确；状态最终来自 Agent；失败时可进入日志或诊断。
  测试要求：正常服务、未安装服务、端口冲突服务各覆盖一次。

- [ ] 任务编号：AC-HOME-003
  模块：启动全部/停止全部
  目标：验证套件操作只处理 auto 服务。
  操作步骤：设置若干服务 auto；点击启动全部；再点击停止全部。
  验收标准：auto=true 且 installed=true 的服务被处理；失败项不阻塞其他项；结果有汇总提示。
  测试要求：至少一个成功、一个未安装、一个端口冲突。

## 7. runtime 安装与导入验收

- [ ] 任务编号：AC-RUNTIME-001
  模块：本地导入 Nginx
  目标：验证导入目录后可启动。
  操作步骤：软件页选择 Nginx 导入目录；提交；回到首页启动 Nginx。
  验收标准：识别 `nginx.exe`；写入 runtime/service/software/config_files；`nginx -v` 可执行；启动后端口监听。
  测试要求：覆盖正确目录、缺少 exe、配置缺失三种场景。

- [ ] 任务编号：AC-RUNTIME-002
  模块：本地导入 PHP
  目标：验证 PHP runtime 可被站点引用。
  操作步骤：导入 PHP 目录，指定或自动分配 FastCGI 端口；启动 PHP。
  验收标准：识别 `php.exe`、`php-cgi.exe`、`php.ini`；版本探测成功；端口监听；网站创建时可选择。
  测试要求：导入两个 PHP 版本用于切换测试。

- [ ] 任务编号：AC-RUNTIME-003
  模块：bundled 安装
  目标：验证随包 runtime 安装/解压闭环。
  操作步骤：选择 bundled 安装；观察进度；安装后启动服务。
  验收标准：解压到独立目录；关键文件存在；数据库登记完整；安装失败清理 staging。
  测试要求：模拟缺包、解压失败、重复安装。

- [ ] 任务编号：AC-RUNTIME-004
  模块：在线下载
  目标：验证下载、校验、解压、探测闭环。
  操作步骤：点击下载安装；观察进度；安装完成后启动。
  验收标准：有真实下载进度；校验哈希/大小；失败不污染正式目录。
  测试要求：网络失败、校验失败、成功安装。

## 8. 服务管理验收

- [ ] 任务编号：AC-SERVICE-001
  模块：启动服务
  目标：验证启动结果可信。
  操作步骤：启动 Nginx 或 PHP。
  验收标准：获取真实 PID；端口监听；健康检查通过；页面显示 running；操作日志记录。
  测试要求：覆盖正常启动、端口占用、可执行文件不存在。

- [ ] 任务编号：AC-SERVICE-002
  模块：停止服务
  目标：验证只停止 WinServer 管理的进程。
  操作步骤：启动服务；停止服务；检查进程和端口。
  验收标准：进程退出；端口释放；页面 stopped；不误杀外部同名程序。
  测试要求：启动外部同名进程，确认不被误杀。

- [ ] 任务编号：AC-SERVICE-003
  模块：后台健康监控
  目标：验证服务异常退出可感知。
  操作步骤：启动服务后从外部结束进程；等待健康轮询。
  验收标准：状态更新为 failed/stopped；保留错误信息；首页展示问题入口。
  测试要求：Nginx、PHP 各一次。

## 9. 网站管理验收

- [ ] 任务编号：AC-SITE-001
  模块：创建站点
  目标：验证站点从表单到访问完整闭环。
  操作步骤：输入域名、目录、端口、PHP；提交；访问域名。
  验收标准：vhost 写入；hosts 写入；Nginx reload；网站可访问；PHP 可执行；刷新应用后站点仍存在。
  测试要求：成功、目录不存在、端口冲突、hosts 无权限。

- [ ] 任务编号：AC-SITE-002
  模块：编辑站点
  目标：验证站点字段变更安全生效。
  操作步骤：修改域名、端口、目录；保存；访问新旧域名。
  验收标准：新配置生效；旧 hosts 清理；旧域名不可访问或不再由 WinServer 管理；失败时旧站点仍可访问。
  测试要求：域名冲突、配置错误、正常编辑。

- [ ] 任务编号：AC-SITE-003
  模块：启用/停用站点
  目标：验证站点可临时下线和恢复。
  操作步骤：停用站点；访问域名；再启用；访问域名。
  验收标准：停用后 vhost/hosts 不再生效；启用后健康检查通过；其他站点不受影响。
  测试要求：停用失败回滚、启用失败保持 disabled。

- [ ] 任务编号：AC-SITE-004
  模块：删除站点
  目标：验证删除不破坏项目源码和其他站点。
  操作步骤：删除站点；检查配置、hosts、数据库、源目录。
  验收标准：站点记录删除；vhost 删除；hosts 记录删除；源目录保留；其他站点正常。
  测试要求：删除最后一个站点、删除多个站点中的一个。

## 10. PHP 切换验收

- [ ] 任务编号：AC-PHP-001
  模块：站点切换 PHP
  目标：验证不同站点可使用不同 PHP 版本。
  操作步骤：创建两个站点，分别选择不同 PHP；访问测试页面；切换其中一个站点 PHP。
  验收标准：两个站点互不影响；切换后实际 `PHP_VERSION` 与选择一致；失败时仍使用旧 PHP。
  测试要求：目标 PHP 未启动、目标 PHP 不完整、Nginx reload 失败、成功切换。

## 13. 日志与诊断验收

## 16. 全量回归验收清单

全量验收必须按顺序执行：

1. [ ] 清理测试数据或准备干净数据目录。
2. [ ] 启动应用，确认首屏体验达标。
3. [ ] 检测本机 runtime。
4. [ ] 导入或安装 Nginx。
5. [ ] 导入或安装 PHP 7.4/8.1/8.3 中至少两个版本。
6. [ ] 启动 Nginx。
7. [ ] 启动第一个 PHP。
8. [ ] 创建第一个站点并访问。
9. [ ] 创建第二个站点并选择不同 PHP。
10. [ ] 验证两个站点使用不同 PHP。
11. [ ] 切换第一个站点 PHP。
12. [ ] 停用第二个站点，确认第一个不受影响。
13. [ ] 启用第二个站点。
14. [ ] 编辑第一个站点端口或目录。
15. [ ] 删除第二个站点，确认源代码目录保留。
16. [ ] 编辑 Nginx 配置并保存。
17. [ ] 注入 Nginx 配置错误并验证回滚。
18. [ ] 查看结构化操作日志，确认关键操作与失败原因可追踪且敏感字段已脱敏。
19. [ ] 检查端口冲突诊断。
20. [ ] 重启应用，确认状态和数据恢复。
